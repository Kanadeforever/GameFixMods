# BALDR SKY Windows 10/11 兼容性审计报告

## 当前核心常开修复

截至 `v0.1-test14`，以下三项已经从“配置项”升级为基础功能：

1. **SteamFix**：Steam `.patch` 三处确定错误；
2. **VideoOverlayFix**：老式视频 Overlay 黑屏；
3. **PixelBoundaryFix**：字体/像素混合左边界前溢 1 像素。

普通用户不能通过 INI 关闭它们。

## SteamFix

已确认 Steam 移植代码有三处错误：

- `LoadLibraryA("GDI32.dll")` 后错误检查 ECX，应检查 EAX；
- `LoadLibraryA("BaldrUtil.dll")` 后同样错误；
- UpdateSteam trampoline 重放 8 字节，却按 5 字节 detour 返回，落入原 CALL 的 rel32 中间。

中英文版均使用语义签名定位，不依赖固定地址；test13 重新离线复核两份实际 EXE，全部结构仍唯一 PASS。

## InstallScript / DPI

Steam 原 `install.vdf` 明确写入：

```text
~ DPIUNAWARE VISTARTM
```

用户实机删除该块后确认 Steam 不再强制兼容/DPI设置，窗口恢复预期 800×600。

兼容层默认静默删除目标 AppCompat 子块并清理当前 EXE 对应 token；只有整个 `install.vdf` 缺失才按游戏语言提示验证完整性，随后继续游戏。

InstallScriptFix 与 HighDpiFix 仍保留用户开关，因为它们会修改持久化 VDF/注册表或明显改变 DPI 行为。

## 视频黑屏

已验证把：

```text
HKCU\Software\Microsoft\Direct3D\Shims\EnableOverlays
```

当前 EXE 路径对应 DWORD 维持为 0 可以解决。test13 起永久启用，不再暴露开关。

## D3D9

同一代理支持：

- Windows 原生 32 位 D3D9；
- 同目录 `d3d9_backend.dll`，例如 DXVK x32。

早期 119 项 COM vtable Probe 已永久删除，因为 test6 证明它会污染系统原生 D3D9。


## ReShade 链式加载

test14 新增可选 ReShade 中间层。它不是新的 Backend：`Backend` 仍只决定最终 D3D9 实现，`EnableReShade` 只决定是否在兼容层和最终后端之间插入 `ReShade32.dll`。

ReShade 6.7 起提供官方 `[PROXY] EnableProxyLibrary / ProxyLibrary` wrapper chaining。兼容层只维护这两个键，并使用最终后端绝对路径避免 DLL 搜索顺序和递归加载。ReShade 缺失或加载失败时自动回退，不影响游戏基本启动。

当前该功能属于 test14 新增功能，等待中文版实机验证；既有 SteamFix、VideoOverlayFix、PixelBoundaryFix 等 PASS 状态不受影响。

## PixelBoundaryFix

这不是“可忽略异常”。中文版存档界面能够稳定导致真实退出。

静态与实机共同确认：

- 故障读取：`mov ecx,[edi]`；
- 目标像素缓冲区由 `[TargetObject+4]` 得到；
- 每像素 4 字节；
- test11 多次严格满足 `EDI=TargetBase-4`；
- test12 改为异常前内联检查后不再崩溃；
- 内联计数至少达到 326，证明属于高频正常 UI 路径。

因此 test13 起永久开启该修复，不提供关闭开关。

## 不默认修改的项目

以下没有足够证据支持默认改动：

- DEP；
- LAA / 2GB 地址空间；
- Nahimic；
- 强制 60Hz；
- Image Cache 128MB；
- 存档路径 Hook；
- DirectSound/DirectInput 全局 Hook；
- 其他社区零散 workaround。

后续中文版实际遇到再定点处理。
