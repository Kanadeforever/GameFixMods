# 八、test4：Steam `call 0` 根因定位

test4 增加：

- 线程 ID；
- `[ESP]` 返回地址；
- 栈；
- 运行时代码；
- ExitProcess/TerminateProcess 等监视。

关键证据：

`FaultReturnAddress=[ESP]=0x00BC0042`

运行时代码：

`0x00BC003C: call dword ptr [0x00BC0107]`

`0x00BC0107` 是 Steam 补丁保存 `BaldrUtil.dll!UpdateSteam` 的函数指针槽。

当时该槽为 0。

因此实际路径：

`Steam 每帧 UpdateSteam`
→ `UpdateSteam 未初始化`
→ `call [0]`
→ `EIP=0`
→ `0xC0000005`

这与最初 WER offset 0 完全吻合。

# 九、Steam `.patch` 三个确定错误

## 错误 1：LoadLibraryA(GDI32) 返回值检查错误

错误：

`test ecx,ecx`

正确：

`test eax,eax`

原因：Win32 x86 `LoadLibraryA` 返回值在 EAX；ECX 是 caller-saved/volatile，调用后没有保留保证。

## 错误 2：LoadLibraryA(BaldrUtil) 同样检查错寄存器

同样应从：

`test ecx,ecx`

改为：

`test eax,eax`

## 错误 3：UpdateSteam trampoline 跳回原 CALL 中间

原函数开头完整重放指令总长度 8 字节：

- `push esi`：1；
- `mov esi,ecx`：2；
- `call rel32`：5。

Steam detour 却按 5 字节返回，导致继续点落进原 `call` 的 rel32 位移字段。

正确继续地址 = 旧目标 +3。

# 十七、test9：高 DPI 默认兼容

用户明确要求：

- 默认开启高 DPI 缩放兼容；
- INI 可以关闭。

实现：

`EnableHighDpiFix=1`

优先：

`SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_SYSTEM_AWARE)`

回退：

`SetProcessDPIAware()`

选择 System DPI Aware，不选择 Per-Monitor V2。

原因：

- BALDR SKY 是固定像素 2009 D3D9 UI；
- System Aware 可以关闭传统 DPI virtualization；
- 不要求旧程序正确处理跨显示器 `WM_DPICHANGED`；
- 更保守。

如果 Windows/manifest/外部兼容层已经提前固定 DPI awareness，兼容层只记录失败并继续启动，不把 DPI 设置失败当致命错误。

# 十九、D3D9 双后端正式结构

## Native

`BaldrSky.exe`
→ `d3d9.dll`（本兼容层）
→ Windows 系统 32 位 `d3d9.dll`

## DXVK

`BaldrSky.exe`
→ `d3d9.dll`（本兼容层）
→ 同目录 `d3d9_backend.dll`（DXVK x32）

自定义后端只按兼容层同目录绝对路径加载，避免 DLL 搜索顺序污染。

`Backend=0`：自动。

`Backend=1`：强制系统 Native。

`Backend=2`：强制自定义，不回退。

# 二十一、存档问题当前结论

历史社区确实存在无法存档、Load 显示 No Data、旧汉化版特定章节存档异常等报告。

静态审计也看到游戏大量使用 ANSI 文件 API，理论上极端文档路径可能有代码页边界风险。

但：

- 当前用户没有复现；
- 报告跨多个老版本/汉化补丁，原因不统一；
- 大范围文件 API Hook 风险高；

因此 test9 **不加入 SavePathFix**。

以后中文版实际遇到再根据当时文件路径/日志做定点修复。
