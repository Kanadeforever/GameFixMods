# BALDR SKY Steam Windows 10/11 兼容层——截至 v0.1-test14 的完整接档

## 一、当前版本与项目目标

当前版本：`BaldrSkyWin11Fix v0.1-test14`

目标：让 Steam 版《BALDR SKY》在现代 Windows 10/11 上以尽可能少的用户操作稳定运行，同时：

- 不依赖用户手工设置 EXE 兼容模式；
- 支持中文 Steam 版与英文 Steam 版；
- 支持 Windows 原生 32 位 D3D9；
- 支持可选 DXVK x32；
- 修复已经通过代码证据和/或实机证据确认的兼容性缺陷；
- 不加入没有稳定证据的“万能兼容补丁”。

当前核心常开修复已经收敛为：

1. **SteamFix**：Steam 移植 `.patch` 的三处确定错误；
2. **VideoOverlayFix**：老式视频有声音但黑屏；
3. **PixelBoundaryFix**：字体/像素混合目标缓冲区左边界前溢 1 个 32bpp 像素。

这三项从 test13 起不再提供 INI 关闭开关。

仍保留用户选择的项目：

- Steam InstallScript/AppCompat 净化；
- High DPI；
- D3D9 后端；
- ReShade 链式加载；
- 日志/诊断。

## 四、Steam `.patch` 的三个确定错误

### 4.1 决定性证据

test4 抓到真正的 EIP=0 路径：

```text
call [UpdateSteamSlot]
UpdateSteamSlot = 0
```

因此原始启动崩溃的直接路径是 Steam 桥没有正确初始化 `UpdateSteam`。

### 4.2 GDI32 LoadLibrary 返回值检查错误

Steam 补丁执行：

```text
LoadLibraryA("GDI32.dll")
```

Win32 返回值在 EAX，但补丁随后测试 ECX。

修复：

```text
85 C9 -> 85 C0
```

即 `test ecx,ecx -> test eax,eax`。

### 4.3 BaldrUtil LoadLibrary 返回值检查错误

第二次加载 `BaldrUtil.dll` 后存在同类错误，同样修为测试 EAX。

### 4.4 UpdateSteam trampoline 返回错位

原函数开头：

```asm
push esi          ; 1 byte
mov esi,ecx       ; 2 bytes
call rel32         ; 5 bytes
```

Steam trampoline 重放总计 8 字节，却按普通 5 字节 detour 继续，跳回原 CALL 的 rel32 中间。

正确目标：

```text
旧目标 + (8 - 5) = 旧目标 + 3
```

历史地址：

- 中文：`0x0060FC85 -> 0x0060FC88`；
- 英文：`0x0060FF15 -> 0x0060FF18`。

这些地址只保留为证据，不作为正式定位输入。

## 五、SteamFix 语义签名

正式实现不写死中文版地址，也不要求中英文字符串连续排列。

扫描器分层验证：

1. 独立定位 `BaldrUtil.dll`、`InitSteam`、`CloseSteam`、`UpdateSteam`、`ResetAchievements`、`GetAchievement`；
2. 找 GDI32 与 BaldrUtil 两次 LoadLibraryA 结构；
3. 要求两次加载使用同一个 LoadLibraryA IAT 槽；
4. 推导 InitSteam / UpdateSteam 函数指针槽；
5. 要求两者共用同一个 GetProcAddress helper；
6. 唯一定位 Steam 初始化入口；
7. 唯一定位 UpdateSteam trampoline；
8. 自动从旧 JMP 目标推导 `+3` 正确续接点。

任意核心结构不是唯一命中：拒绝修改，不猜第一处。

## 九、Steam `install.vdf` 与 AppCompat

用户发现 Steam 启动游戏前会恢复兼容/DPI设置。

最终确认 `install.vdf` 明确包含：

```text
%INSTALLDIR%\BaldrSky.exe = "~ DPIUNAWARE VISTARTM"
```

位置：

```text
HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers
```

这会在进程创建阶段强制：

- DPI Unaware；
- Vista compatibility layer。

### 当前方案

默认 `EnableSteamInstallScriptFix=1`。

第一次运行时静默：

1. 唯一定位目标 VDF 子块；
2. 首次保留 `install.vdf.baldrskywin11fix.bak`；
3. 用临时文件完整写出修改结果；
4. 原子替换正式 `install.vdf`；
5. 从当前 EXE 的 Layers 字符串中只剔除 `DPIUNAWARE` / `VISTARTM`；
6. 其他用户 token 保留；
7. 不自动重启游戏；
8. Steam 更新/验证恢复 VDF 后，下次启动再次静默处理。

用户已实机确认：VDF 处理通过，Steam 后续不再重新写回强制兼容/DPI值。

### install.vdf 整体缺失

只在文件完全不存在时弹 MessageBox：

- 中文游戏 -> 中文提示；
- 英文游戏 -> 英文提示；
- 建议验证 Steam 文件完整性；
- 用户关闭提示后继续游戏，不退出。

读取失败、文件异常等其他错误只记日志，不误报“文件缺失”。

## 十、HighDpiFix

默认：

```ini
EnableHighDpiFix=1
```

设置进程为 System DPI Aware，关闭 Windows 传统 DPI 虚拟化。

故意不用 Per-Monitor V2，因为 BALDR SKY 是 2009 年固定像素 UI，没有针对 `WM_DPICHANGED` 和跨显示器动态 DPI 切换设计。

用户已确认：InstallScriptFix 处理完成后，窗口恢复预期 800×600，不再被放大到约 1000×7xx，日志确认 System DPI Aware 成功。

HighDpiFix 仍保留用户开关，因为它属于可见窗口行为；与三个基础稳定性核心修复不同。

## 十三、PixelBoundaryFix 根因

中文版 `BaldrSky.bin` 静态反汇编：

```asm
006C1AC8  mov edx,[esp+38h]
006C1ACC  mov edi,[edx+4]       ; TargetBase
...
006C1B15  lea edi,[edi+eax*4]   ; 目标像素地址
...
006C1B98  movzx edx,word ptr [ebx]
006C1B9B  mov ecx,[edi]         ; 实际 AV
...
006C1C12  mov [edi],ebx
006C1C14  add edi,4
```

这是 32bpp 目标像素混合/字体绘制路径。

## 十四、test11 决定性实机验证

test11 暂不改变正常代码，只在目标 AV 发生后严格验证现场。

用户实机多次得到：

```text
EDI=0x1C6CFFFC  TargetBase=0x1C6D0000  Delta=-4
EDI=0x25CEFFFC  TargetBase=0x25CF0000  Delta=-4
EDI=0x27DFFFFC  TargetBase=0x27E00000  Delta=-4
```

即：

```text
EDI == TargetBase - 4
```

随后只把 EIP 改到原函数自己的：

```asm
006C1C14  add edi,4
```

存档界面不再崩溃。

结论：

> 左边界裁剪少跳过恰好 1 个 4 字节目标像素。

## 十五、test12 异常前内联修复

### 15.1 为什么从异常恢复升级

test11 非常适合验证根因，但长期不应该让 Access Violation 成为正常控制流。

### 15.2 运行时扫描

test12 要求以下结构全部唯一：

#### A. 像素混合核心

```text
0F B7 13 8B 0F 81 E2 00 FF FF FF C1 E2 10 3B D1 76
```

#### B. 目标对象来源

故障点前 0x100 内唯一：

```asm
mov edx,[esp+XX]
mov edi,[edx+4]
```

`XX` 自动推导，中文版为 `0x38`。

#### C. 安全续接

故障点后 0x100 内唯一：

```asm
mov [edi],ebx
add edi,4
```

### 15.3 中文离线结果

```text
内联补丁点：0x006C1B98
故障读取点：0x006C1B9B
正常返回点：0x006C1B9D
越界像素续接：0x006C1C14
目标对象栈偏移：0x38
```

全部唯一 PASS。

### 15.4 运行时行为

5 字节入口 JMP 到动态 RX 跳板。

跳板：

- 重放原 `movzx`；
- 取当前 TargetObject / TargetBase；
- 若 `EDI == TargetBase-4`：直接走原函数的像素推进续接；
- 否则完整执行原 `mov ecx,[edi]` 并返回正常路径。

只裁掉已经确定位于目标表面左边界外的那个像素。

### 15.5 页面保护

- `VirtualAlloc`：先 RW；
- 写跳板；
- `VirtualProtect` -> RX；
- `FlushInstructionCache`；
- 游戏代码页临时可写，仅修改 5 字节入口；
- 恢复原保护；
- 再 Flush。

不会长期留下 RWX 页。

### 15.6 安全回退

结构唯一但内联安装失败：自动使用 test11 精确异常恢复。

结构本身非唯一：拒绝修改。

原 `OverlayGuardIntervalMs` 不再暴露在 INI。

固定内部：


属于实现细节，不值得增加普通用户配置负担。

### 18.3 日志默认

```ini
EnableLog=0
LogLevel=3
EnableCrashDiagnostics=1
```

设计目的：

- 正常玩家：完全不生成日志；
- 小白遇到问题：只需把 `EnableLog=1`；

纯诊断异常处理器只在：

```text

AND
```

这样默认 `EnableLog=0` 时不会为了不可见日志增加诊断干预。

但是 PixelBoundaryFix 的 test11 fallback 属于核心稳定性，不属于“诊断”：

> 只要内联安装失败，无论日志/CrashDiagnostics 开关如何，都自动安装精确恢复。

## 二十、失败/放弃方案汇总

1. **把 NVIDIA 原生 D3D9 当唯一根因**：错误，DXVK 同样复现原启动故障。
2. **全量 119 项 Device vtable Probe**：污染系统原生 D3D9，正式永久删除。
3. **SteamFix 固定绝对地址**：只适合早期验证，正式改为语义签名。
4. **依赖 EXE 属性页兼容/DPI设置**：Steam `install.vdf` 会重写，改为源头净化。
5. **把 `0x006C1B9B` 当正常 first-chance AV**：已撤回，存档界面可稳定实际退出。
6. **长期依赖异常恢复**：test11 只用于验证/安全 fallback；正式走 test12 内联检查。
7. **预防性 SavePath/LAA/DEP/Nahimic/60Hz 等大范围 Hook**：证据不足，不默认加入。
8. **把三个基础修复继续暴露为用户开关**：test13 删除，避免误关。

## 二十七、test14 ReShade 链式加载

### 27.1 目标

原项目必须占用游戏目录的 `d3d9.dll`，而 ReShade 的传统 D3D9 wrapper 也需要同名入口。test14 不改变主入口归属，而是把 ReShade 作为可选中间层。

### 27.2 文件布局

```text
BaldrSky.exe
d3d9.dll
d3d9.ini
ReShade32.dll          # 可选，ReShade 32 位 DLL
ReShade.ini            # ReShade 自己的配置
d3d9_backend.dll       # 可选，例如 DXVK x32
```

不使用子目录。项目包不附带第三方 ReShade DLL/shader。

### 27.3 配置语义

```ini
[Graphics]
Backend=0
EnableReShade=0
```

两项独立：

- `Backend` 只决定最终 D3D9 实现；
- `EnableReShade` 只决定是否把 `ReShade32.dll` 插到兼容层与最终后端之间。

因此组合关系为：

```text
ReShade OFF: BaldrSky -> Fix -> Native/DXVK
ReShade ON : BaldrSky -> Fix -> ReShade32 -> Native/DXVK
```

### 27.4 ReShade ProxyLibrary

ReShade 6.7 起官方加入 wrapper chaining：

```ini
[PROXY]
EnableProxyLibrary=1
ProxyLibrary=<path>
```

test14 在 `LoadLibrary(ReShade32.dll)` **之前**只维护这两个键。其他 ReShade INI 内容不重写。

`ProxyLibrary` 使用最终后端**绝对路径**：

- DXVK/自定义后端：指向同目录 `d3d9_backend.dll` 的绝对路径；
- Native：指向 Windows 系统 32 位 `d3d9.dll` 的绝对路径。

这样可避免 DLL 搜索顺序污染，并避免 Native 模式下 ReShade 再次命中本兼容层 `d3d9.dll` 形成递归。

### 27.5 安全回退

`EnableReShade=1` 时，如果：

- `ReShade32.dll` 不存在；
- `ReShade.ini` 的 PROXY 键无法写入；
- DLL 无法加载；
- DLL 不导出 `Direct3DCreate9`；

则自动回退到已经由 `Backend` 选出的最终后端，不让可选图形后处理破坏游戏基本启动。

`Backend=2` 仍保留原语义：如果用户明确要求强制 `d3d9_backend.dll` 而该 DLL 本身不可用，就不回退 Native。
