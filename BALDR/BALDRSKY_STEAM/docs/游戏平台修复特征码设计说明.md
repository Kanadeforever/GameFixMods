# SteamFix 语义特征码设计说明

## 目标

正式修复不能依赖中文版固定绝对地址。

地址只作为“扫描结果和历史证据”记录，不作为定位输入。

## 分层验证

### 1. 独立语义字符串

分别唯一定位：

```text
BaldrUtil.dll
InitSteam
CloseSteam
UpdateSteam
ResetAchievements
GetAchievement
```

英文版允许中间插入自定义字体、设备初始化等额外字符串。

### 2. 两次 LoadLibraryA 结构

分别确认 GDI32 与 BaldrUtil 的加载路径，并要求二者使用同一个 LoadLibraryA IAT 槽。

### 3. 导出函数指针槽

通过 `push <slot> / push <function-name> / call helper` 推导 InitSteam 和 UpdateSteam 槽，并要求共用同一 GetProcAddress helper。

### 4. Steam 初始化入口

要求唯一匹配调用 helper、检查 InitSteam 槽和调用初始化函数的完整入口。

### 5. UpdateSteam trampoline

完整匹配保存/恢复寄存器、`call [UpdateSteamSlot]`、重放原始 8 字节和最终 JMP。

修复目标根据：

```text
旧目标 + (8 - 5) = 旧目标 + 3
```

运行时计算，不写死中文版/英文版地址。

## 安全策略

任意核心结构不是唯一命中：

- 不修改；
- 不取第一处猜测；
- 开日志时明确报告命中数。

## test13 离线复核

实际中文/英文 Steam EXE 再次扫描均 PASS：

- 中文：`0x0060FC85 -> 0x0060FC88`；
- 英文：`0x0060FF15 -> 0x0060FF18`。

SteamFix 从 test13 起属于核心常开功能，不再提供 INI 关闭开关。

## test14

ReShade 功能不修改 SteamFix 扫描/补丁算法。test14 继续使用 test13 已复核的中英文语义签名。
