# 字体像素边界崩溃修复说明

## 现象

中文版在存档/读档界面移动鼠标、切换存档槽即可稳定触发实际崩溃。

固定故障读取：

```asm
006C1B9B  mov ecx,[edi]
```

多次运行时地址不同，但均满足：

```text
AccessAddress == EDI
EDI == TargetBase - 4
```

## 根因

目标表面是 32bpp 像素缓冲区，每像素 4 字节。

旧代码在左边界裁剪时仍多处理一个像素，把目标地址算成缓冲区起点前 4 字节，于是读取了左边界外一个像素。

## test11 验证

异常发生后只在严格满足：

```text
EDI == TargetBase - 4
```

时跳到原函数自己的：

```asm
add edi,4
```

用户实机不再崩溃，根因被直接坐实。

## test12 正式内联方案

长期实现不再把 AV 当正常控制流。

运行时唯一定位：

1. 像素混合核心特征；
2. `mov edx,[esp+XX] / mov edi,[edx+4]` 的目标对象来源；
3. `mov [edi],ebx / add edi,4` 的安全续接。

随后在非法读取发生前判断：

```text
如果 EDI == TargetBase - 4：
    跳过这个左边界外像素
否则：
    完整执行原来的 mov ecx,[edi]
```

## 实机价值

用户在原本稳定崩溃的存档界面持续操作，游戏不再崩溃，内联修复累计至少触发 326 次。

这证明该 bug 会在正常 UI/字体绘制中高频发生，不是偶发 first-chance 异常。

## test13 起的发布状态

PixelBoundaryFix 已升级为**核心永久开启功能**，不再提供 `EnablePixelBoundaryFix` 配置项。

正常模式使用内联检查；如果内联安装失败，无论日志是否开启，都会自动回退 test11 精确异常恢复。

## test14

test14 只新增 ReShade 链式加载，不修改 PixelBoundaryFix 算法；中文版 test12 的 326+ 次内联拦截 PASS 结论继续作为当前稳定基线。
