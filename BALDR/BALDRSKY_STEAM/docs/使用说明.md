# BALDR SKY Steam Windows 11 兼容层 v0.1-test9 使用说明

## 当前定位

`v0.1-test9` 是在 test8 已经完成中英文 SteamFix、视频黑屏修复、Native/DXVK 双后端之后的正式候选测试版。

这一版默认开启三类兼容功能：

1. **Steam 移植补丁修复**
   - 修正两处 `LoadLibraryA` 返回值错误检查；
   - 修正 `UpdateSteam` trampoline 跳回原指令中间的问题；
   - 使用中英文共用语义签名，不依赖固定地址。

2. **老式视频黑屏修复**
   - 自动维护 `HKCU\Software\Microsoft\Direct3D\Shims\EnableOverlays`；
   - 当前 `BaldrSky.exe` 完整路径对应 DWORD 始终保持为 `0`；
   - 英文版 test8 已实机确认该值能正确创建并在退出游戏后保持为 0。

3. **高 DPI 缩放兼容**
   - 默认把 BALDR SKY 设置为 `System DPI Aware`；
   - 关闭 Windows 对老式非 DPI-aware 程序的传统 DPI virtualization；
   - 默认开启，可在 `d3d9.ini` 中关闭；
   - 故意不使用 Per-Monitor V2，避免给 2009 年固定像素 UI 引入跨显示器 DPI 动态切换回归。

同一个 `d3d9.dll` 仍同时支持：

- Windows 原生 32 位 D3D9；
- DXVK x32（改名为 `d3d9_backend.dll`）。

## 安装

把：

- `release\d3d9.dll`
- `release\d3d9.ini`

复制到 `BaldrSky.exe` 同目录。

或者运行：

`release\deploy_test9.bat`

部署脚本只复制预编译文件，不进行任何编译。

## 推荐测试基线

`BaldrSky.exe` 属性页保持全部默认：

- 不开 Windows 7 / Windows 8 兼容模式；
- 不要求管理员；
- 不勾禁用全屏优化；
- 不在 EXE 属性页手工设置 DPI；
- 不关闭系统 DEP。

高 DPI 行为由本兼容层自己的 INI 控制。

---

## 高 DPI 设置

默认：

```ini
[Compatibility]
EnableHighDpiFix=1
```

含义：

- 兼容层会尝试把当前进程设置为 `System DPI Aware`；
- Windows 不再对旧程序做传统 DPI 虚拟化；
- 游戏固定像素窗口尺寸更接近真实物理像素；
- 不启用 Per-Monitor V2。

如果发现窗口尺寸、鼠标坐标或某个特殊环境不符合预期，可关闭：

```ini
EnableHighDpiFix=0
```

关闭后兼容层完全不修改 DPI awareness。

详细原理见《高DPI缩放说明.md》。

---

## 原生 D3D9 模式

游戏目录不要放 `d3d9_backend.dll`：

```text
BaldrSky.exe
d3d9.dll
d3d9.ini
```

`Backend=0` 时会自动使用 Windows 系统 32 位 D3D9。

也可以强制：

```ini
[Graphics]
Backend=1
```

---

## DXVK 模式

把 DXVK x32 的 `d3d9.dll` 改名为：

`d3d9_backend.dll`

放到兼容层同目录：

```text
BaldrSky.exe
d3d9.dll             <- 本兼容层
d3d9.ini
d3d9_backend.dll     <- DXVK x32
```

`Backend=0` 会自动优先使用它。

`Backend=2` 可以强制自定义后端；如果文件不存在则直接报错，不回退系统 D3D9。

---

## 视频黑屏修复

默认：

```ini
EnableVideoOverlayFix=1
```

兼容层只操作：

`HKCU\Software\Microsoft\Direct3D\Shims\EnableOverlays`

中以当前 `BaldrSky.exe` **完整路径**为值名的 DWORD。

启动时写 `0`，之后守护线程定期检查；只有值被改回非 0 时才再次写入。

不会修改其他程序对应的值。

---

## SteamFix

默认：

```ini
EnableSteamFix=1
```

如果签名不是唯一命中，兼容层会安全拒绝写内存并在日志中报告；不会“猜第一处”强行补丁。

中英文实际 EXE 已用包内扫描工具复核 PASS。

---

## 诊断

正式候选默认：

```ini
[Diagnostics]
EnableLog=1
LogLevel=2
EnableCrashDiagnostics=0
```

`EnableCrashDiagnostics=0` 的原因：test8 已观察到英文版/图形后端存在能被自身处理的 first-chance 异常。长期使用时默认把它们写成“AV”容易造成误判。

以后如果真的再次退出/崩溃，只需要临时改为：

```ini
EnableCrashDiagnostics=1
```

即可重新启用 VEH/VCH 现场记录。
