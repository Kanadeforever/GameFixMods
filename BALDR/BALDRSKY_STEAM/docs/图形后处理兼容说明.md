# ReShade 图形后处理兼容说明

## 目标

BALDR SKY Win11 兼容层本身必须占用游戏目录的 `d3d9.dll`，而 ReShade 的传统 D3D9 安装方式也要占用同名文件。test14 通过链式加载解决冲突，不需要子目录。

## 文件布局

```text
BaldrSky.exe
d3d9.dll              # BALDR SKY Win11 Fix
d3d9.ini
ReShade32.dll          # ReShade 32 位 DLL，可选
ReShade.ini            # ReShade 配置
d3d9_backend.dll       # DXVK x32，可选
```

项目包**不附带 ReShade 二进制或 shader 文件**。请从 ReShade 官方来源取得。

## 配置

```ini
[Graphics]
Backend=0
EnableReShade=1
```

`Backend` 与 `EnableReShade` 独立：

| Backend | ReShade | 调用链 |
|---:|---:|---|
| 0 | 0 | 兼容层 -> 自动选择 DXVK/Native |
| 1 | 0 | 兼容层 -> Native |
| 2 | 0 | 兼容层 -> d3d9_backend.dll |
| 0 | 1 | 兼容层 -> ReShade -> 自动选择 DXVK/Native |
| 1 | 1 | 兼容层 -> ReShade -> Native |
| 2 | 1 | 兼容层 -> ReShade -> d3d9_backend.dll |

## ReShade.ini 管理范围

ReShade 6.7 起官方支持 wrapper chaining。兼容层在加载 `ReShade32.dll` 之前自动写：

```ini
[PROXY]
EnableProxyLibrary=1
ProxyLibrary=<最终 D3D9 后端的绝对路径>
```

只管理这两个键。其他 ReShade 配置、preset、shader 搜索路径、输入热键等保持原样。

使用绝对路径的原因：

- 自定义后端不会被 DLL 搜索顺序劫持；
- Native 模式不会因为写 `d3d9.dll` 而重新命中本兼容层，避免递归。

## 版本要求

- 游戏是 Win32/x86，因此必须使用 ReShade 32 位 DLL；
- wrapper chaining 需要 ReShade 6.7 或更新版本；
- 当前开发时官方稳定版为 6.8.0。

## 失败回退

如果 `EnableReShade=1`，但：

- 没有 `ReShade32.dll`；
- `ReShade.ini` 的 PROXY 项无法写入；
- ReShade DLL 无法加载；
- DLL 没有 `Direct3DCreate9` 导出；

兼容层会记录错误（启用日志时）并直接使用已经选好的最终 D3D9 后端，不因为可选图形后处理导致游戏无法启动。

`Backend=2` 是例外：它本来就表示“强制自定义后端”，因此 `d3d9_backend.dll` 自身不可用时仍按原语义报错，不回退 Native。
