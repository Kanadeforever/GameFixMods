# 构建说明

## 用户不需要构建

正式预编译文件位于：

```text
release\d3d9.dll
```

## 工具链

- Clang 17；
- LLD 17；
- target：`i686-pc-windows-msvc`。

## 构建特点

- Win32 / x86；
- 无 CRT；
- 无 Windows SDK 头文件依赖；
- 普通 Import Directory 为空；
- 仅导出 `Direct3DCreate9`；
- `/dynamicbase`；
- `/nxcompat`；
- `/Brepro` 可复现构建。

## PixelBoundaryFix 内联跳板

运行时使用动态解析的：

- `VirtualAlloc`；
- `VirtualProtect`；
- `FlushInstructionCache`。

流程：

1. RW 分配；
2. 写入 x86 跳板；
3. 切换为 RX；
4. FlushInstructionCache；
5. 修改游戏 5 字节入口 JMP；
6. 恢复游戏代码页原保护并再次 Flush。

不会长期留下 RWX 页。

## test13 代码收敛

- 删除 SteamFix / VideoOverlayFix / PixelBoundaryFix 的 INI 字段、读取逻辑和关闭分支；
- Overlay 500ms 守护间隔收回内部常量；
- 默认 `EnableLog=0`；
- 默认 `LogLevel=3`；
- 默认 `EnableCrashDiagnostics=1`；
- 纯诊断 VEH/VCH 只有 `EnableLog=1 && EnableCrashDiagnostics=1` 时安装；
- PixelBoundaryFix fallback 独立于日志配置。

## 一键构建

开发者可运行：

```text
source\build.bat
```

BAT 为 UTF-8 + CRLF。

最终 DLL 大小、SHA-256 和可复现构建结论见《文件清单与校验值.md》。

## test14 ReShade 链式加载

新增动态解析 `WritePrivateProfileStringA`，只用于维护 `ReShade.ini` 的 `[PROXY]` 两个键；仍不增加普通 PE Import Directory。

D3D9 加载器重构为两阶段：

1. 根据 `Backend` 先选出并验证最终后端；
2. `EnableReShade=1` 时，再加载同目录 `ReShade32.dll` 作为中间层。

ReShade 或配置写入失败时退回第一阶段选出的最终后端。
